## Контекст лекции недели 5 (RAG)

Лекция `videossummary/05_RAG_…`: **RAG — это анти-галлюцинации**. Модель отвечает из retrieved-чанков
во время инференса, а не из «общей тренировочной базы». Метаданные `source/section/chunk_id` кладутся
в промпт явно (задел дня 21–22), чтобы модель могла сослаться на источник и процитировать фрагмент.

Ключевые понятия из лекции, применённые в день 24:
- **Косинусное сходство** как мера релевантности: `score ∈ [-1, 1]`, `1` = идентичны. Низкий score =
  чанк нерелевантен → основание для отказа («не знаю»).
- **Чанки + метаданные** — основа для источников/цитат (source, section, chunk_id).
- **Анти-галлюцинации** — модель не должна выдумывать при слабом контексте; программный canned-response
  гарантирует отказ лучше, чем LLM-генерация (которая может проигнорировать инструкцию).
- **Метрика качества** — правдивость ответов: проверяем источники + цитаты, а не только keyword coverage.

## Маппинг задания → реализация

| Требование задания | Реализация |
|---|---|
| модель обязательно возвращает ответ | `ContextAwareAgent.chat()` всегда возвращает ответ (canned «не знаю» ИЛИ LLM-ответ) |
| список источников (source + section/chunk_id) | усиленный промпт `PromptBuilder.renderRetrievedBlock` требует раздел «Источники» с `source › section (chunk_id)` |
| цитаты (фрагменты из найденных чанков) | усиленный промпт требует раздел «Цитаты» с дословными фрагментами в кавычках «...» |
| проверить на 10 вопросах: источники в каждом ответе | `/rag eval` с колонкой `RAG src` (✓/✗) через `CitationDetector` |
| проверить на 10 вопросах: цитаты в каждом ответе | `/rag eval` с колонкой `RAG cite` (✓/✗) через `CitationDetector` |
| совпадает ли смысл ответа с цитатами | пост-чек `CitationDetector` в `finalizeAssistant` (warning); substring-overlap ≥40 chars проверяет дословность |
| усиление: «не знаю» при релевантности ниже порога | `RagConfig.dontKnowThreshold` + `CannedResponses.weakContext()` — canned без LLM |

## Решения и обоснования

### 1. Программный canned-response, не LLM-генерация отказа

Задание: «ассистент обязан сказать не знаю». LLM-генерация отказа (`temperature=0.0` + промпт
«откажись») — платно и нет жёсткой гарантии (модель может проигнорировать). Программный canned-response:
- 100% гарантия отказа (нет вызова LLM = нет галлюцинации);
- бесплатно (0 токенов);
- persist'ится в history как обычный assistant-ответ (корректная сериализация).

### 2. Пост-чек warning-only, не re-prompt

Задание требует обязательных источников/цитат. Re-prompt (если `CitationDetector` не нашёл источники —
повторный запрос к LLM с напоминанием) даёт максимальную гарантию, но дорого (до 2× LLM-вызовов на
ответ) и сложно тестировать. Выбран **warning-only**: промпт требует структуру, пост-чек логирует
нарушения, но не блокирует. Дёшево, прозрачно, метрика видна в `/rag eval`.

### 3. `dontKnowThreshold` отдельно от `similarityThreshold`

`similarityThreshold` (день 23) — фильтрует чанки для реранкера (`ThresholdReranker.filter { score >= threshold }`).
`dontKnowThreshold` (день 24) — отказывается отвечать при слабом контексте в целом (max similarity
среди финальных чанков < порога). Разные семантики → разные поля. Default `0.0` для обоих → backward-compat.

### 4. Расширение корпуса + переписывание eval-вопросов

Аудит выявил: дефолтные `corpusRoots` НЕ индексировали `AGENTS.md` и `.kt`-исходники, но 7/10 вопросов
ссылались на `AGENTS.md` (невалидно). Решение: расширить корпус + переписать вопросы на 10 нестандартных
фактов из разных файлов (числа, алгоритмы, имена enum'ов). Каждый вопрос теперь имеет валидный source.

### 5. Live-таймер + серая строка (UX)

`withSpinner(labelProvider)` уже пересчитывает лейбл каждые 120ms — добавлен `withTimedSpinner`,
который вставляет `HH:MM:SS` (через `System.nanoTime()` в closure). Серая строка после ответа —
mordant `gray` (ANSI 256 тёмно-серый, fallback на plain при `--no-color`).
