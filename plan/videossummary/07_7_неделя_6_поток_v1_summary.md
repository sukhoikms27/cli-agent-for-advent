### Саммари лекции: Неделя 7 — Сборка Production-Ready AI-систем

#### 1. Краткое описание лекции

Это заключительная, самая практическая неделя курса, посвященная сборке всех полученных знаний в единую, работающую систему. Основной фокус — создание AI-агентов как мини-операционных систем, делегирование задач субагентам, интеграция с системными инструментами (System Tools, MCP) и построение надежных AI-пайплайнов с мониторингом и обработкой ошибок. Главная цель — дать слушателям время для создания реального прототипа или продукта на основе пройденного материала.

#### 2. Основные темы

- **LLM Agent как мини-ОС:** Концепция современного AI-агента, который управляет инструментами и ресурсами, подобно операционной системе.
- **Создание субагентов:** Паттерны делегирования задач (Fan-out, Chain, Router) для решения сложных, многошаговых задач без потери контекста.
- **Системные инструменты (System Tooling):** Интеграция с файловой системой, bash-командами, MCP и RAG для расширения возможностей агента.
- **AI-пайплайны:** Построение автоматизированных цепочек (триггер -> агент -> действие) на примере автоматического ревью кода.
- **Production-готовность:** Обработка ошибок (Error Handling), метрики (Latency, Cost, Quality), тестирование и внедрение Human-in-the-Loop.

#### 3. Ключевые концепции и термины

- **LLM Agent как мини-ОС:** Агент, имеющий доступ к инструментам (файлы, MCP, bash) и способный самостоятельно управлять ресурсами для выполнения задачи. Примеры: Cursor, Claude Code, OpenCode.
- **Субагент (Sub-agent):** Специализированный агент, созданный для решения одной конкретной подзадачи в рамках более крупной задачи. Имеет собственное контекстное окно, что предотвращает его переполнение у основного агента-оркестратора.
- **Паттерны делегирования:**
    - **Fan-out:** Оркестратор параллельно запускает несколько субагентов для независимых задач (например, рефакторинг бэкенда и мобильного приложения одновременно).
    - **Chain (Цепочка):** Агенты выполняются последовательно, где результат одного является входом для другого.
    - **Router (Маршрутизатор):** Агент выбирает, какого субагента запустить, на основе условия или типа запроса.
- **System Tools:** Набор инструментов для взаимодействия с окружением: чтение/запись файлов, выполнение bash-команд, запуск приложений.
- **Tool Executor & Tool Registry:** Архитектурный паттерн, где все инструменты регистрируются в едином реестре, а Executor по запросу LLM находит и запускает нужный инструмент, возвращая результат.
- **Dangerous Operations:** Опасные операции (удаление файлов, git push), которые требуют обязательного подтверждения от пользователя (Human-in-the-Loop).
- **AI Pipeline:** Автоматизированный процесс, запускаемый по триггеру (PR, расписание, событие), который включает в себя AI-агента для обработки входных данных и получения результата.
- **Error Handling & Fallback:** Стратегии обработки сбоев: Retry (повтор с другим промптом/моделью), Fallback (альтернативная стратегия или уведомление человека), Timeouts.
- **Метрики AI Pipeline:**
    - **Latency (Время):** Персентили (P50, P95, P99) времени выполнения.
    - **Cost (Стоимость):** Расход токенов на одну операцию (например, на PR).
    - **Quality (Качество):** Оценка полезности результата человеком (например, по шкале 1-10).
    - **Success Rate (Процент успеха):** Доля прогонов, не потребовавших вмешательства человека.

#### 4. Практические выводы / что нужно сделать

1.  **Спроектировать свою мини-ОС:** Подумать, как сделать так, чтобы пользователь решал задачу за одну сессию, не отвлекаясь на потерю контекста.
2.  **Внедрить субагентов:** Для сложных, недетерминированных задач (например, "спланируй поездку") разбить процесс на подзадачи и делегировать их специализированным субагентам. Использовать паттерны Fan-out, Chain или Router.
3.  **Реализовать систему инструментов:** Создать Tool Registry и Tool Executor для управления всеми инструментами (файлы, MCP, RAG). Обязательно добавить проверку на опасные операции с запросом подтверждения у пользователя.
4.  **Построить AI-пайплайн:** Начать с простого примера, например, автоматического ревью кода при создании Pull Request.
5.  **Настроить обработку ошибок:** Прописать стратегии Retry, Fallback и уведомления человека для критических случаев. Не допускать полностью автоматических процессов без возможности вмешательства.
6.  **Внедрить метрики и тестирование:**
    - Замерить baseline по времени, стоимости и качеству.
    - Тестировать пайплайн на исторических данных (эталонные примеры).
    - Сравнивать версии промптов и моделей по метрикам.
7.  **Создать реальный продукт:** Использовать эту неделю для сборки прототипа, который решает реальную задачу, а не просто демонстрирует технологию.

#### 5. Цитаты / важные моменты

- "LLM Agent это, по сути, мини-OS в современном мире."
- "Наша задача сделать так, чтобы задача пользователя была решена за минимальное количество итераций пользователя с этим сервисом. В идеале, чтобы он просто один раз сказал, что делать, и все."
- "Если бы вы их использовали, цепи в чейне, они бы работали там 16, 17, 20 минут. Как только вы начинаете использовать агентов в параллель, это время же сразу же сокращается в 2, в 3, в 4, а то и в 10 раз иногда."
- "Есть опасные операции... в идеале вы должны у себя настроить отдельный анализ... и спрашивать у юзера."
- "Мы должны всегда предусмотреть хьюмана в этой цепи, то есть не должно быть такого, что ваш сервис полностью автоматический."
- "Я вам максимально рекомендую на этой неделе расслабиться, выдохнуть... берите реальные продукты, пробуйте, внедряйте, делитесь опытом, ошибайтесь, это самое важное."
