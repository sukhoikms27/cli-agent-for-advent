## Что реализовано (3 оптимизации)

### 1. ModelLimits qwen3:14b → 40960 (точный context budget)
`src/main/kotlin/com/cliagent/llm/ModelLimits.kt` — добавлена точная запись:
```
"qwen3:14b" to ModelLimits(contextWindow = 40_960, maxOutput = 8_192)
```
`forModel()` сначала проверяет точное совпадение → "qwen3:14b" резолвится в 40960, а qwen3:7b/32b —
в generic "qwen3" → 128K. Предотвращает 3x-завышение. Влияет на `OutputBudget` (точный clamp) и
`contextLimit` warning.

### 2. contextLimit из registry (не хардкод 128K)
`src/main/kotlin/com/cliagent/cli/ChatCommand.kt` — в `buildSession()`:
```
contextLimit = ModelLimitsRegistry.forModel(model).contextWindow
```
Теперь warning о превышении контекста срабатывает на реальном пороге модели (qwen3:14b → 40K,
glm-5.1 → 200K), а не на хардкоде 128000.

### 3. Prompt-адаптация для local RAG (`SystemPrompts.localRag`)
`src/main/kotlin/com/cliagent/llm/model/SystemPrompts.kt` — новый task-specific промпт:
- Жёсткое требование отвечать ТОЛЬКО из `[Retrieved context]`, не выдумывать.
- Явно называть source (file › section) — без требования дословных цитат (14B плохо их генерирует).
- Признание незнания («не знаю») — анти-галлюцинация.
- Лимит 150 words — против многословности локальных моделей.
Включается в `buildSession` когда `resolvedProvider == OLLAMA && config.rag.enabled`; cloud → default.

## Архитектурные решения

1. **Точная запись qwen3:14b перед generic qwen3** — `forModel()` exact-match приоритет. qwen3:7b/32b
   продолжат prefix-match в generic "qwen3" → 128K (no regression). Additive (schema evolution).
2. **contextLimit из registry, не хардкод** — единый source of truth в `ModelLimitsRegistry`. При
   добавлении новой модели contextLimit автоматически корректен.
3. **localRag conditional (provider==OLLAMA && ragEnabled)** — cloud-сессии используют default
   (backward-compat). Ветвление в `buildSession`, не в агенте (агент остаётся provider-агностичным).
4. **GenerationPresets wiring отложен** — enum мёртвый код, wiring требует temperature val→var + maxTokens
   не из пресета. Это отдельная задача; day 29 фокусируется на измеримых оптимизациях (ModelLimits + prompt).
