## План (опция MED из Research, вариант B1)

Команда `/rag compare-local [N]` — side-by-side сравнение на одном retrieved-контексте:
- Fair compare: `retrieve()` ОДИН раз на вопрос → одинаковый промпт обоим клиентам.
- Метрики: keyword coverage, citation score (`CitationDetector`), latency, длина ответа.
- Graceful-деградация: нет cloud API key → local-only режим.
- Handler в `ChatCommand` (есть `savedCloudConfig`), не в `RagCommands`.

## Архитектурные решения

1. **Fair compare — один retrieved-контекст**: `retrieve()` вызывается один раз на вопрос, промпт
   идентичен обоим клиентам. Разница в ответах → только генеративная способность модели, не retrieval.
2. **Handler в ChatCommand (вариант B1)**: `savedCloudConfig` приватно в ChatCommand — handler живёт
   там же, не расширяет конструктор `RagCommands`. Создаёт двух клиентов через `LlmClientFactory.create()`.
3. **Прямой `client.chat()` без агента**: изолирует генеративную модель от stateful-логики
   (memory/tools/invariants). RAG-контекст строится вручную (как `renderRetrievedBlock` дня 22/24).
4. **Graceful-деградация**: `cloudClient` создаётся в try/catch → `null` если нет API key.
   Compare работает в local-only, partial credit (метрики local vs baseline).
5. **Опциональный аргумент N**: `/rag compare-local 3` — первые N вопросов. Ускоряет демо на медленных
   локальных моделях (qwen3 ~40с/вопрос).
