# Чеклист проверки — Sprint 7 (консольное приложение «Заметки»)

## Критерии успешного выполнения задания

Каждый пункт оценивается ✅ (выполнено) или ❌ (не выполнено):

1. **Есть меню с возможностью добавления и просмотра архивов.**
   Пользователь может создать архив и увидеть список существующих архивов.

2. **Есть меню с возможностью добавления и просмотра заметок.**
   Внутри архива можно создать заметку и увидеть список заметок этого архива.

3. **Есть возможность добавлять и просматривать текст заметок.**
   Экран заметки отображает её текст; заметка создаётся с текстом.

4. **Приложение не позволяет создать архив или заметку без имени (с пустым именем).**
   Должна быть проверка: пустое имя отклоняется, пользователю сообщается об ошибке.

5. **Приложение не позволяет создать заметку без содержания (с пустым текстом).**
   Должна быть проверка: пустой текст заметки отклоняется.

6. **Нет повторений одного и того же кода. Вся логика по считыванию ввода пользователя
   и выводу пунктов на экран должна переиспользовать один и тот же код.**
   Общая логика (печать пунктов, чтение ввода, диспетчер выбора) вынесена в отдельный
   класс (например, абстрактный `Screen`/`Menu` + `ScreenHandler`). Меню архивов и
   заметок не должны дублировать эту логику — они наследуют/используют общий код.

7. **Ошибочный ввод пользователя должен корректно обрабатываться.**
   - Если ввели не цифру → программа сообщает «следует вводить цифру» и повторяет меню.
   - Если ввели цифру за пределами списка → программа сообщает «такой цифры нет» и повторяет меню.
   - Программа **не падает** с `NumberFormatException`/`IndexOutOfBoundsException`.

8. **Из любого меню можно выйти и попасть на предыдущее меню или выйти из программы,
   если это просмотр архива.**
   - Меню заметок → возврат к меню архива.
   - Меню архива → выход из программы.
   - Единственный выход из программы — из верхнего меню (архивов).

9. **Приложение успешно компилируется и выполняется без ошибок.**
   `./gradlew build` проходит; запуск не падает сразу.

10. **Весь код не написан в одном файле Main.**
    Код разделён по файлам (по одному классу/ответственности на файл): `Archive.kt`,
    `Note.kt`, `Screen.kt`, `ScreenHandler.kt`, `Main.kt` и т.п. Файл `Main.kt` содержит
    только `fun main()`.

11. **Весь код приложения написан на Kotlin.**
    (Тривиально для Kotlin-проекта, но проверяется.)

## Авторское решение (эталон)

`Screen` (abstract) + `ScreenHandler` (object) + `Data` (interface) — общий каркас навигации
и ввода/вывода. Конкретные экраны (`TopScreen`, `ArchiveScreen`, `NoteScreen`) наследуют
`Screen` и реализуют только специфичную логику. Данные (`ArchiveData`, `NoteData`, `Notepad`)
реализуют `Data`. Разделение по файлам: один класс — один файл.

## Рекомендации по проверке

- Флаговать только нарушения пунктов чеклиста, баги и дублирование кода.
- Студенты только что перешли с Java на Kotlin — не требовать идиом (`when`, `?.let`,
  `data class`, `runCatching`), если код работает корректно. Лучше soft-рекомендация.
- Ссылаться на https://kotlinlang.org где уместно (например, `toIntOrNull`, `isBlank`).
