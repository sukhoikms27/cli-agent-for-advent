## Контекст кодовой базы (из Research)

Интеграция локальной LLM в CLI-агент **уже выполнена в день 25** (`LlmClientFactory` + `OpenAiCompatibleClient` без auth-header для Ollama). Поэтому день 27 — это:

1. **Доделать live-switch** (если начат в день 26) — runtime-переключение local↔cloud без рестарта `chat`. Сейчас `/config set provider ollama` warns «Restart chat to apply».
2. **Бонус-тумблер** (из видео-саммари нед.6, 4-е задание): переключение локальная↔облачная **с маркировкой результатов** — пользователь видит, какой моделью сгенерирован ответ (`[local:qwen3:14b]` vs `[cloud:glm-5.1]`).
3. **Полноценный end-to-end прогон** приложения полностью на локальной модели (без `CLI_AGENT_API_KEY`): REPL-сессия с историей, контекст-стратегией, /stats, /cost.

## Что добавить в код

1. **Runtime provider switch** — `/provider local` / `/provider cloud` / `/provider <name>` пересоздаёт `LlmClient` + агента в работающем REPL (по образцу `plan/extensions/08-runtime-chat-switching.md`).
   - Требует рефакторинга: вынести создание client/agent в переиспользуемую функцию `buildAgent(config)`, вызываемую при старте и при switch.
2. **Маркировка ответов** — в REPL-выводе префикс/бейдж с именем провайдера+модели. mordant-цвета: local=yellow, cloud=blue.
3. **`/cost` для локальных** — сейчас `Pricing.calculateCost()` возвращает `null` для qwen3. Показать «local (free)» вместо пустоты.
4. **Тесты** — runtime-switch (mock), маркировка, cost для local.

## Архитектурные инварианты

- Live-switch не должен ломать персистентную историю (chatId сохраняется).
- `CancellationException` не глотать (корутины).
- backward-compat: cloud-only сессия работает идентично дню 25.
- Маркировка — опциональна (config-флаг `markProvider`), off by default для backward-compat вывода.
